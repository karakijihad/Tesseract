# This tree is sealed

You are inside `app/` — the TESSERACT application. It is a checkout, not a
workspace. **Do not edit anything here.**

Not because the files are precious, but because edits here are silently
destroyed: every update replaces this tree wholesale (`git fetch` +
`checkout_head --force`, and a failed re-clone deletes the directory outright).
Work you do here disappears at the next update, with no diff, no conflict and
no warning. It will look like your change simply never happened.

## The three directories

```
<install>/
├── app/        ← you are here. Read freely. Write nothing.
├── home/       ← the user's world. Everything you produce goes here.
└── runtime/    ← machine-local: venv, caches, pidfiles, ops logs.
```

`home/` is writable and portable — it is what the user copies between
machines. `runtime/` is generated by provisioning and is not yours either.

## What to do instead

- **Scratch work, drafts, notes, experiments** → the `home` tree's `workshop/<task>/`
- **Downloads** → its `downloads/` · **Research sources** → its `vault/raw/`
- **Anything the user asked you to produce** → somewhere under `home`

If you were asked to change the application itself — fix a bug in the runtime,
add a tool, edit a prompt — that work belongs in the **development repository**,
not here. This tree is the built artifact. Say so and stop; do not approximate
the fix by editing the installed copy. A change made here reaches nobody: it is
not in git, it will not survive the next update, and no one will ever review it.

## Reading is fine

Read anything. Grep it, trace it, quote it. "Read-only" means readable — the
point of shipping the source is that the agent running inside it can understand
itself. The seal is on writing, and only on writing.
